# 数据模型与解释边界

每个组件版本结果包含来源、固定 commit 或 Registry 版本身份、独立观测的内容哈希、解析器版本、文件清单及逐条定义。扫描输入变动后生成新的结果；主索引只引用每个已配置来源当前接受的版本，历史记录保留。

定义保存 `symbol`、`expression`、`file`、`line`、`source_url`、`conditions`、`role`、`resolution`、`value`、`alias_of`、`base_symbols`、`config_symbols`。尚未解析的数值使用 JSON `null`，不以零或默认 BASE 代替。

- `resolved`：受支持的常量表达式已求值，且未记录预处理条件；不是编译验证。
- `conditional`：数值已求值，但定义附有预处理条件；尚未验证条件能否成立或共同成立。
- `unresolved`：缺少配置/引用、表达式不支持、类型语义不确定或引用有歧义。
- `reviewed`：精确匹配的人工规则提供了数值；保留解释和证据，不自动证明项目中生效。

Kconfig 保存涉及配置文件的符号块原文；不执行完整 Kconfig 解释器，外围 menu/if、source 和依赖图尚未完全建模，因此它是定位线索，不是某个目标的配置解。

默认根据名称推测 `_BASE`、`_MAX`、`_END`、`_COUNT` 的角色。它们始终留在明细中，但不计入普通错误码重叠。公共 `ESP_OK`/`ESP_FAIL` 和直接别名同样不作为独立占用。命名不符合约定时需要人工规则。

数值集合保持稀疏；汇总中的最小值和最大值只是包络，不表示中间每个数值都被使用。组件自己的保留区间须在后续加入带来源证据的独立模型，当前不自动推断。

重叠分为 `numeric-overlap` 和 `conditional-overlap`。相同来源定义去重，但复制代码、fork、不同包中的同源定义没有自动血缘证明，仍需人工复核。可配置且未求值的定义不参与数值比较，也不能据此判定无冲突。当前不生成“项目内确认冲突”结论。

Registry 证据链接指向固定版本页面；`file` 和 `line` 是实际发布 ZIP 内文件的位置，配合包 URL、ZIP SHA-256 与逐文件哈希复核。不能将 Registry 行号拼到任意 GitHub 分支上。GitHub 证据链接则直接固定到扫描 commit 的文件和行号。

解析器更改求值、候选发现或归类行为后，必须递增 `PARSER_VERSION`，防止复用旧逻辑的结果。接口适配或来源设置的语义变化同样应触发重新扫描。升级时通过测试与小范围真实扫描验证后再扩大重算范围。

文件选择逻辑使用独立的 `SELECTION_VERSION`，它也参与分析输入指纹。`evidence.selection` 记录模式、候选数、选择数、跳过数、公开头文件候选和回退原因。`public-headers` 仅按静态 CMake 声明和组件内 include 闭包缩小范围，不证明源码定义都已覆盖；对实现文件内部的定义需要 `full` 模式审计。

`evidence.excluded_submodules` 记录显式跳过的子模块路径及提交；这些内容未被读取。`evidence.context_headers` 记录显式加载的同仓库、同提交公共头文件，它们计入下载、文件和内容哈希预算，但不计入该组件的定义集合。组件文件选择数量不包含这些额外公共文件；完整文件清单包含它们。`context_references` 为受影响定义保留被引用符号的文件、行号、表达式和固定提交链接。共享头文件只辅助受支持表达式求值，不推断真实构建的 include 顺序，也不放宽条件或歧义检查。

网页翻译限于界面文案，原始标识符和证据保持原文；语言选择不影响 JSON 数据。构建为脚本、样式和索引 URL 添加内容哈希，以避免更新后浏览器混用不同版本的资源。

首页将可求值记录转换为稀疏数值区段，仅在状态和组件集合相同、且数值连续时合并。空洞独立显示；负数按有符号数值顺序展示，显示范围为 −2³¹ 至 2³¹−1。图高按区段数值数量的对数压缩，不代表线性占比；区段高度设有上下界。尚未求值的配置表达式保留在数据页，并在范围查询中提示未参与比较。
